## 媒体库 401 修复（media.php）

## ⚠️ 重大事故与恢复：theme:ecod-theme 被覆盖（20:46-20:50）
- 根因：测试夹具用 PHP serialize 读改写 theme:ecod-theme，但 Typecho 1.3 该行存 **JSON**（内核 tryDeserialize 两种都读），unserialize 失败返回 [] 后整个配置被覆盖成只剩 ENavSets 一个键
- 发现：前台渲染正常但配置只剩 1 键；DB 中 value 长度 700（原 6233）
- 恢复：mysqlbinlog ROW 格式前镜像。mysqlbinlog -v -v --base64-output=DECODE-ROWS --start-datetime ... binlog.000023，按 `### WHERE` 段取 @3（注意同 block 里 SET 段也有 @1..@3，必须先按 WHERE/SET 切分再取），MySQL 转义（\n \t \\ \' \Z \0 等）手工反转义后 json 校验（77 keys）。写回后字节级一致（6233）
- 教训（已固化）：
  1. 永远不要用 serialize 写 typecho_options；theme:ecod-theme 必须 json_decode/json_encode
  2. 任何直接改 DB 测试数据的脚本，写入前必须先备份原值（cp 或另存 option 行）
  3. mysql -N -B 导出含转义字段必须加 --raw，否则 JSON 被二次转义损坏
  4. 站点 binlog 开着（ROW 格式，/opt/homebrew/var/mysql/），出事可用前镜像恢复；-v -v 输出中 WHERE=旧值 SET=新值

## 付费 / 会员可见 · 设计方案（docs/paywall-design.md）
- 参考 Zibll zibpay 拆解：采纳「文章级 pay_mode + 会员价 + 付费卡 + hide 扩展 + 订单判定」，不采纳 6 种 pay_type、游客 Cookie 订单、user_meta 存会员、jQuery/Vue 后台。
- 实验结论（重要，已插桩验证后恢复）：
  1. `Widget\Archive::singleHandle()` 在 `themeInit()` 之前读 `plainExcerpt`（Archive.php:1705）→ 单篇 `content` 已缓存，`contentEx` 钩子对文章页无效；post.php 里「只注册基类会漏掉」的注释即由此而来。
  2. Feed 每条新建 Archive，contentEx 在 themeInit 后触发（实测 14 次命中）→ 可作 Feed/列表兜底。
  3. 因此门禁分四层：L1 post.php 模板硬门禁、L2 ecod_excerpt 摘要层、L3 contentEx Feed 兜底、L4 shortcode_strip 搜索层，共同调用 `ecod_pay_access()`。

- 通道抽象 `EcodPayChannel`：manual / card / epay（易支付 MD5），回调用 `UPDATE ... WHERE status='pending'` + affectedRows 做幂等。
- UI：收银台走独立页模板 page-cashier.php（复用特色页），付费卡与 ecod_replybox 同一视觉语言；列表角标 pay/vip。
