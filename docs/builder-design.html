Ecod Builder 设计说明

自研页面构建器 —— 在现有 blocks 体系上演进「板块堆叠布局 + 页面级归属 + 所见即所得画布」。

状态：草案 v1 · 2026-10-31 · 参考：guaqi.com/builder（板块堆叠模式）、既有 core/admin/blocks.php v4 体系

1 目标与非目标

1.1 一句话目标

站长在后台以所见即所得方式，把 54 个现有模块与新的「板块」容器自由组合，按页面类型 / 分类 / 单页三个粒度灵活布局网站，前台渲染性能与现有模板持平。

1.2 目标

  • 灵活布局：板块（全宽 section）→ 内部「主体 + 可选侧栏」→ 模块纵向堆叠，板块控制宽度 / 内边距 / 背景 / 明暗。
  • 页面级归属：布局可绑定到页面类型（home/page/cat…）、某分类（cat:12）、或某一页（cid:23），带回退链。
  • 所见即所得：iframe 加载真实前台页面，点击选中、拖放插入、右侧属性面板即时生效。
  • 零重写：现有 54 个模块模板、params schema、媒体/图标选择器、渲染引擎全部复用；v4 数据自动兼容。

1.3 非目标（明确不做）

  • 自由画布 / 任意行列嵌套（参考对象瓜奇也不是这种模式）；
  • 设备级三套数据树（用「单数据源 + 容器查询」替代，见 8.1）；
  • 第三方运行时插件、多语言字段、云端模板市场、多前端。

2 总体架构

不新起平行系统，blocks 体系原地升级 v4 → v5：编辑端新增画布壳，数据层新增「布局文档」，渲染层在 ecod_widgets_render() 之前插入板块渲染器并向下兼容。

编辑端 新增assets/admin/builder.js / builder.css

  • iframe 活体预览 + 覆盖层
  • 统一字段渲染器 Inspector
数据层 升级core/admin/blocks.php + builder.php
  • 布局文档 v5（sections 树）

3 数据模型

3.1 布局文档（Layout Document，v5）

核心结构：页面 → 板块列表 → 板块（box 样式 + 栏配置）→ 模块实例。模块实例复用 v4 的 {uid,type,on,params}，叶子完全兼容。

{
  "v": 5,
  "rev": 42,
  "docs": {
    "home":   { "sections": [ /* 板块数组 */ ] },
    "cat:12": { "sections": [ ... ] },
    "cid:23": { "sections": [ ... ] }
  }
}

// 单个板块 section：
{
  "uid": "sec_a1b2",
  "on": 1,
  "label": "精选推荐",                    // 编辑器里显示的名字
  "box": {
    "width": "full",                      // full | boxed
    "contentMax": 1200,                   // 内容最大宽度 px，0=跟随主题
    "padY": 48,                           // 上下内边距 px
    "bg": "", "bgDark": "",               // 明/暗背景（色值或图片 URL）
    "radius": 0,
    "tone": "auto"                        // auto | light | dark   板块级明暗
  },
  "cols": {
    "type": "stack",                      // stack | aside-left | aside-right
    "asideWidth": 320,                    // 侧栏宽度 px，200–420
    "asideSticky": 1                      // 侧栏吸顶
  },
  "main":  [ { "uid":"slider-1","type":"slider","on":1,"params":{...} } ],
  "aside": [ { "uid":"hot-1","type":"hot","on":1,"params":{...} } ]
}

约束：stack 时 aside 必须为空数组；单文档板块数 ≤ 30；每栏模块数 ≤ 20（沿用 ECOD_WIDGET_LIMIT 语义）。

3.2 存储

内容位置说明
页面类型默认布局（home/page/cat/tag/search/author/custom）options 表独立行 ELayouts（user=0）与 EWidgets 同款：JSON + rev 乐观锁 + schema 版本字段
分类 / 单页覆盖（cat:12、cid:23）新表 ecod_page_layoutid, kind(cat|cid), ref, doc JSON, rev, updated；照抄 core/lib/schema.php 的 ensure 自愈模式；行数少，key 查询走主键
v4 旧数据EWidgets 原样保留回退链末级，永不迁移销毁（见 6.4）

3.3 渲染回退链

ecod_layout_resolve( 当前页面 ):
  cid:页cid  →  cat:主分类  →  页面类型默认  →  (未命中) EWidgets v4 旧区域

每一级都是整页替换而非合并（与瓜奇「按 ID 精确绑定」语义一致），避免局部合并带来的理解成本。未启用 v5 的站点（ELayouts 为空）整个链条短路到 v4，行为与现状完全一致。

4 组件设计

4.1 板块容器：注册表扩展而非新体系

板块不是「第 55 个模块」，而是布局文档的结构节点；但它在编辑器里以模块库卡片的形式出现。在 blocks-def.php 追加声明：

ecod_block_define('section', [
  'name' => '板块', 'icon' => 'gg-layout',
  'area' => 'layout',                       // 新区域类型：只在布局文档中出现
  'params' => [
    'width' => ['type'=>'select','options'=>['full','boxed'],'default'=>'full'],
    'contentMax' => ['type'=>'number','min'=>0,'max'=>1920],
    'padY' => ['type'=>'number','min'=>0,'max'=>200,'default'=>48],
    'bg' => ['type'=>'image'], 'bgDark' => ['type'=>'image'],
    'tone' => ['type'=>'select','options'=>['auto','light','dark']],
    // cols / 栏配置为结构字段，不走 params，由文档树直接持有
  ],
]);

4.2 统一字段渲染器（Field Registry）P1 关键

现状：widget.js:1015-1420 的参数面板是命令式 JS，设置页字段走 Typecho 原生 Element。构建器 Inspector 需要第三处渲染，若再抄一份会形成三套漂移。设计为声明式注册表：

window.EcodFields = {
  types: { text, number, switch, select, textarea,
           image,        // → EcodMedia.pick
           icon,         // → 图标弹层（合并 nav.js / widget.js 两套现成实现）
           color, spacing, repeater /* 支持一级嵌套 */ },
  render(fieldDef, value, onChange) → HTMLElement
}
消费方改造
Builder Inspector（新）直接调用 registry
widget.js 参数面板P1 逐步替换内部实现为 registry，对外行为不变
设置页 config.js暂不动（原生 Element 是保存载体）；仅新增字段类型时经 registry 出控件

嵌套 repeater：服务端 ecod_wgt_clean_repeater() 增加 fields 递归清洗（深度 ≤ 2），前端 registry 的 repeater 渲染器同步支持子 schema。这是现有清洗器的唯一功能性扩展。

4.3 编辑器前端组件拆分

assets/admin/builder.js 内部按职责拆为六个模块（esbuild 按 1:1 minify，不 bundle，保持单文件即可，用注释分节）：

组件职责来源
Store布局文档状态、脏跟踪、undo 栈（环形 50 步，操作粒度=文档 JSON diff）新建（纯函数 diff，参考 nav.js 摊平/重建思路）

Inspector右侧属性面板，按选中对象（板块/模块）出 schema 表单EcodFields registry
Outline板块/模块大纲树，点击定位、拖拽排序nav.js 树拖拽算法
Saver保存队列、rev 冲突处理、快照（复用 core/admin/snapshot.php）widget.js 保存队列平移

4.4 服务端入口 builder.php 新增

独立入口，模式与 widget.php 完全一致（管理员 + CSRF + JSON 响应）：

5.3 属性面板信息架构

右栏随选中对象切换，两组标签页：

  • 选中模块 → 「内容」（params schema 全量字段）/「样式」（壳参数：density、shell、移动端隐藏）；
  • 选中板块 → 「板块设置」（box + cols）/「背景」（明/暗两套图 + 色值）/「高级」（板块级自定义 CSS，P2，见 6.5）。

模块参数改动即时生效：Inspector onChange → Store 更新 → 对该模块单独发起 canvas.render 片段请求（只重渲染该模块 HTML，替换 iframe 内对应节点），避免整页刷新闪烁。

6 重要逻辑设计

6.1 渲染管线（前台）

function ecod_layout_render( $page_type, $widget ) {
  $doc = ecod_layout_resolve( $page_type );        // 3.3 的回退链
  if ( !$doc ) return ecod_widgets_render_legacy(); // v4 原路径，零风险出口
  foreach ( $doc['sections'] as $sec ) {
    if ( empty($sec['on']) ) continue;
    echo ecod_section_open( $sec );                 // 输出 box 样式 + 栏容器
      ecod_layout_col( $sec['main']  );             // 复用 ecod_render_block()
      ecod_layout_col( $sec['aside'] );
    echo ecod_section_close();
  }
}
  • 板块壳输出语义化 DOM：<section class="ecod-sec" style="--sec-pad-y:48px;--sec-max:1200px">，样式走新增的 CSS 分节（ecod.css 追加 「41. Builder 板块」编号头，遵守 critical CSS 分节纪律）；
  • 响应式：列表类模块改用 container-type: inline-size 让卡片列数随容器自动减列（板块窄容器自然生效）；板块级只有两个响应式行为——移动端隐藏开关、aside 自动堆叠（≤900px 时侧栏落到主体下方）；
  • 缓存：布局文档解析结果并入现有 core/lib/cache.php TTL 文件缓存，保存时按 key 失效。

6.2 画布模式（iframe 内发生了什么）

iframe 加载 ?ecod_builder=1 的真实页面（真实登录态、真实数据）：

  • 该标记下渲染层做三件事：① 每个板块/模块壳注入 data-buid；② 尾部注入一段很小的 bridge.js（拖放命中计算、点击上报、片段替换）；③ 屏蔽前台交互副作用（表单提交、PJAX、弹窗内链跳转改为上报）；
  • bridge.js 只在 builder 标记存在时输出，前台正常访问路径零注入、零 JS；
  • 板块样式改动（padY/bg/宽度）通过 postMessage 下发 CSS 变量热更新，不重渲染。

6.4 保存与迁移（v4 → v5）

  • 保存：文档级整存整取（不做板块级增量写），POST 携带 rev，409 时提示「已被另一窗口修改」并支持取回远端 diff——沿用 widget.js 现成的脏队列 + 冲突 UI；
  • 迁移：惰性——首次进入构建器时若 ELayouts 为空，把 v4 各区域现有实例按顺序包成「每区一个板块」的文档副本（v4 数据保留不动），用户取消则继续走 v4；
  • 快照：每次保存前自动落一份 ecod-snap-builder-*（复用 core/admin/snapshot.php，上限 10 份滚动）。

8 决策记录

#决策理由 / 放弃项
8.1 单数据源 + 容器查询，不做瓜奇的三设备数据树 三套树需要同步工具与冲突处理（瓜奇为此做了「同步到其他设备」整套机制），单人维护成本差一个数量级；主题已有成熟断点体系，列表减列用 container query 即可覆盖 90% 场景。板块级仅留「移动端隐藏」「aside 自动堆叠」两个逃生口。
8.2 blocks 原地升级 v5，不新建平行 builder 系统 渲染端与编辑端本就分离（widget.js 自述渲染走前台块模板）；54 个模块零改动，v4 数据短路兼容，风险分散在三期而非一次重写。
8.3 板块 = 结构节点，不做成第 55 个模块 板块承载树结构（main/aside 栏），模块实例不能有 children——避免出现「模块套文档」的递归歧义；但板块的 box 参数仍走 params schema，清洗与面板复用同一套机制。
8.4 覆盖层画选中态，不在 iframe 内注入编辑 UI iframe 内只注入 3KB bridge，前台样式零污染；覆盖层坐标 = getBoundingClientRect × 缩放比，实现简单且随主题暗色模式自动适配。
8.5 整页替换而非局部合并布局 回退链任一级命中即整页接管，语义与瓜奇一致、心智简单；「全局区 before/after」的合并语义保留在 v4 路径，v5 文档自身支持显式复用（模板导入）。
