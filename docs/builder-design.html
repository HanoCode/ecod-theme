Ecod Builder 设计说明

自研页面构建器 —— 在现有 blocks 体系上演进「板块堆叠布局 + 页面级归属 + 所见即所得画布」。

状态：v1.0 已实现（P0+P1 核心，2026-10-31） · 参考：guaqi.com/builder（板块堆叠模式）、WordPress 页面构建器（Gutenberg / Elementor / Beaver Builder / Divi / Breakdance 等，见 §9）、既有 core/admin/blocks.php v4 体系
实现记录：入口 builder.php，数据层 core/admin/builder-doc.php（ELayouts 行 + ecod_page_layout 表，schema v15），板块壳样式在 ecod.css §42（§41 已被正文渲染增强占用）。与设计的一处偏差：未用 bridge.js / postMessage 桥——画布 iframe 与编辑器同源，builder.js 直接在 iframe 文档上以捕获阶段接管交互（点击/拖放/键盘），比协议桥更少一层；若未来出现跨域部署场景再补桥。大纲树上移/下移已实现；「板块分组折叠在模块管理台」「模板导入导出」「批量修改」仍属 P2。

1 目标与非目标

1.1 一句话目标

站长在后台以所见即所得方式，把 54 个现有模块与新的「板块」容器自由组合，按页面类型 / 分类 / 单页三个粒度灵活布局网站，前台渲染性能与现有模板持平。

1.2 目标

  • 灵活布局：板块（全宽 section）→ 内部「主体 + 可选侧栏」→ 模块纵向堆叠，板块控制宽度 / 内边距 / 背景 / 明暗。
  • 页面级归属：布局可绑定到页面类型（home/page/cat…）、某分类（cat:12）、或某一页（cid:23），带回退链。
  • 所见即所得：iframe 加载真实前台页面，点击选中、拖放插入、右侧属性面板即时生效。
  • 零重写：现有 54 个模块模板、params schema、媒体/图标选择器、渲染引擎全部复用；v4 数据自动兼容。

1.3 非目标（明确不做）

  • 自由画布 / 任意行列嵌套（参考对象瓜奇也不是这种模式）；
  • 设备级三套数据树（用「单数据源 + 容器查询」替代，见 8.1）；
  • 第三方运行时插件、多语言字段、云端模板市场、多前端。

2 总体架构

不新起平行系统，blocks 体系原地升级 v4 → v5：编辑端新增画布壳，数据层新增「布局文档」，渲染层在 ecod_widgets_render() 之前插入板块渲染器并向下兼容。

编辑端 新增assets/admin/builder.js / builder.css
  • 画布壳（顶栏 / 模块库 / 大纲）
  • iframe 活体预览 + 覆盖层
  • 统一字段渲染器 Inspector
数据层 升级core/admin/blocks.php + builder.php
  • 布局文档 v5（sections 树）
  • 存储：options 行 ELayouts + per-cid 表
  • 白名单清洗 + rev 乐观锁（沿用）
▲ 保存（POST + CSRF）　　　▼ 渲染（PHP，前台零 JS）
渲染层 小改core/admin/blocks.php:ecod_render_block
  • ecod_layout_render()：板块壳 + 栏分配
  • 54 个模块模板零改动继续消费
  • 画布模式注入 data-buid + 编辑脚本
复用资产 不动现有基建
  • blocks-def.php 模块注册表（54 个）
  • EcodMedia.pick / 图标弹层 / build.mjs
  • token 体系 + .ecod_widget 壳

3 数据模型

3.1 布局文档（Layout Document，v5）

核心结构：页面 → 板块列表 → 板块（box 样式 + 栏配置）→ 模块实例。模块实例复用 v4 的 {uid,type,on,params}，叶子完全兼容。

{
  "v": 5,
  "rev": 42,
  "docs": {
    "home":   { "sections": [ /* 板块数组 */ ] },
    "cat:12": { "sections": [ ... ] },
    "cid:23": { "sections": [ ... ] }
  }
}

// 单个板块 section：
{
  "uid": "sec_a1b2",
  "on": 1,
  "label": "精选推荐",                    // 编辑器里显示的名字
  "box": {
    "width": "full",                      // full | boxed
    "contentMax": 1200,                   // 内容最大宽度 px，0=跟随主题
    "padY": 48,                           // 上下内边距 px
    "bg": "", "bgDark": "",               // 明/暗背景（色值或图片 URL）
    "radius": 0,
    "tone": "auto"                        // auto | light | dark   板块级明暗
  },
  "ov": {                                 // 断点覆盖白名单（Elementor 式，见 9.3）
    "sm": { "padY": 24, "hide": 1 }       // md=平板 sm=手机；仅覆盖写出的键，其余继承桌面值
  },
  "cols": {
    "type": "stack",                      // stack | aside-left | aside-right
    "asideWidth": 320,                    // 侧栏宽度 px，200–420
    "asideSticky": 1                      // 侧栏吸顶
  },
  "main":  [ { "uid":"slider-1","type":"slider","on":1,"params":{...} } ],
  "aside": [ { "uid":"hot-1","type":"hot","on":1,"params":{...} } ]
}

约束：stack 时 aside 必须为空数组；单文档板块数 ≤ 30；每栏模块数 ≤ 20（沿用 ECOD_WIDGET_LIMIT 语义）。

ov 覆盖键仅限白名单字段（padY / hide / tone），未写出的键继承桌面值——单文档即可表达设备级微调，避免演变成三套数据树（见 8.1 修正案与 9.3）。

3.2 存储

内容位置说明
页面类型默认布局（home/page/cat/tag/search/author/custom）options 表独立行 ELayouts（user=0）与 EWidgets 同款：JSON + rev 乐观锁 + schema 版本字段
分类 / 单页覆盖（cat:12、cid:23）新表 ecod_page_layoutid, kind(cat|cid), ref, doc JSON, rev, updated；照抄 core/lib/schema.php 的 ensure 自愈模式；行数少，key 查询走主键
v4 旧数据EWidgets 原样保留回退链末级，永不迁移销毁（见 6.4）

3.3 渲染回退链

ecod_layout_resolve( 当前页面 ):
  cid:页cid  →  cat:主分类  →  页面类型默认  →  (未命中) EWidgets v4 旧区域

每一级都是整页替换而非合并（与瓜奇「按 ID 精确绑定」语义一致），避免局部合并带来的理解成本。未启用 v5 的站点（ELayouts 为空）整个链条短路到 v4，行为与现状完全一致。

4 组件设计

4.1 板块容器：注册表扩展而非新体系

板块不是「第 55 个模块」，而是布局文档的结构节点；但它在编辑器里以模块库卡片的形式出现。在 blocks-def.php 追加声明：

ecod_block_define('section', [
  'name' => '板块', 'icon' => 'gg-layout',
  'area' => 'layout',                       // 新区域类型：只在布局文档中出现
  'params' => [
    'width' => ['type'=>'select','options'=>['full','boxed'],'default'=>'full'],
    'contentMax' => ['type'=>'number','min'=>0,'max'=>1920],
    'padY' => ['type'=>'number','min'=>0,'max'=>200,'default'=>48],
    'bg' => ['type'=>'image'], 'bgDark' => ['type'=>'image'],
    'tone' => ['type'=>'select','options'=>['auto','light','dark']],
    // cols / 栏配置为结构字段，不走 params，由文档树直接持有
  ],
]);

4.2 统一字段渲染器（Field Registry）P1 关键

现状：widget.js:1015-1420 的参数面板是命令式 JS，设置页字段走 Typecho 原生 Element。构建器 Inspector 需要第三处渲染，若再抄一份会形成三套漂移。设计为声明式注册表：

window.EcodFields = {
  types: { text, number, switch, select, textarea,
           image,        // → EcodMedia.pick
           icon,         // → 图标弹层（合并 nav.js / widget.js 两套现成实现）
           color, spacing, repeater /* 支持一级嵌套 */ },
  render(fieldDef, value, onChange) → HTMLElement
}
消费方改造
Builder Inspector（新）直接调用 registry
widget.js 参数面板P1 逐步替换内部实现为 registry，对外行为不变
设置页 config.js暂不动（原生 Element 是保存载体）；仅新增字段类型时经 registry 出控件

嵌套 repeater：服务端 ecod_wgt_clean_repeater() 增加 fields 递归清洗（深度 ≤ 2），前端 registry 的 repeater 渲染器同步支持子 schema。这是现有清洗器的唯一功能性扩展。

4.3 编辑器前端组件拆分

assets/admin/builder.js 内部按职责拆为六个模块（esbuild 按 1:1 minify，不 bundle，保持单文件即可，用注释分节）：

组件职责来源
Store布局文档状态、脏跟踪、undo 栈（环形 50 步，操作粒度=文档 JSON diff）新建（纯函数 diff，参考 nav.js 摊平/重建思路）
Library左栏模块库：blocks-def 生成、搜索、拖出widget.js 现成 DnD 逻辑平移
Canvasiframe 加载与缩放、iframe 内命名空间 chrome 调度、shield 拖拽、postMessage 收发editor.js iframe 预览经验
Inspector右侧属性面板，按选中对象（板块/模块）出 schema 表单EcodFields registry
Outline板块/模块大纲树，点击定位、拖拽排序nav.js 树拖拽算法
Saver保存队列、rev 冲突处理、快照（复用 core/admin/snapshot.php）widget.js 保存队列平移

4.4 服务端入口 builder.php 新增

独立入口，模式与 widget.php 完全一致（管理员 + CSRF + JSON 响应）：

action说明
doc.get / doc.save读/写布局文档；save 携带 rev，白名单清洗后 bump
layout.list / deleteper-cid / per-cat 覆盖的增删（ecod_page_layout 表）
canvas.render带 ?ecod_builder=1 标记输出前台 HTML（供 iframe 加载，见 6.2）
template.export / import整页模板 JSON 导入导出（P2）

4.5 壳样式 supports 注册表（Gutenberg 式）P1

Gutenberg 的 block.json 用 supports 声明块参与的通用能力（颜色 / 间距 / 锚点…），编辑器按声明出控件、渲染层按声明套通用样式。把同一机制引入模块声明，替代「往 54 个模块里逐个加参数」：

ecod_block_define('hot', [ ..., 'supports' => [
  'density', 'shell',          // 现有壳参数，默认全量
  'anchor',                    // P2：输出 id 锚点（配合锚点导航 / 菜单跳转）
  'css',                       // P2：实例级自定义 CSS（见 6.5 纪律）
  'hide-sm',                   // 移动端隐藏（并入 ov 白名单）
]]);
  • Inspector 按 supports 渲染对应控件组（控件本身全部来自 EcodFields registry），模块只声明「我参与哪些通用能力」，不自带重复参数；
  • 渲染层按 supports 输出壳属性与 CSS 变量（沿用 data-density / data-shell 通道），前台零额外成本；
  • 新能力（如「上外边距微调」）= registry 加一种控件 + supports 开关，54 个模块一次性获得。

5 UI 设计

5.1 编辑器整体布局与区域规格

三段式 + 顶栏 + 状态栏。与主题设置页同一视觉语言（token 体系、圆角/描边三档、rest 靠描边不靠阴影）。编辑器壳是固定框架、面板内部滚动——各面板独立滚，互不牵动。给分析用的硬规格：

区域尺寸折叠 / 响应职责
顶栏 Topbar高 48px，固定<1280px 隐藏中组（设备切换移入状态栏）文档、设备、历史、保存
左栏 Library / Outline宽 264px，内部滚动可折叠为 48px 图标轨；1280–1439px 默认收起模块库 + 大纲树（双 tab）
画布 Canvasflex 剩余，最小 640px始终可见iframe 工作台 + 缩放
右栏 Inspector宽 312px，内部滚动1024–1279px 变滑出抽屉；无选中时显示「页面设置」（文档级背景、板块外上下边距等）选中对象的属性
状态栏 Statusbar高 28px<1280px 并入顶栏缩放、脏状态、连接状态

编辑器自身可用性下限：<1024px 不再适配，画布上方出提示条「页面构建器建议在桌面端使用」并提供只读大纲模式——不为移动端管理维护第二套编辑 UI（与前台访客的触屏体验无关，前台路径零影响）。

5.1.1 顶栏控件清单

组控件行为细节
左组退出 · 文档选择器 退出：脏状态先弹「保存 / 放弃 / 取消」三选；文档选择器下拉列出全部文档（home、cat:N、cid:N…），当前项带「绑定来源」徽标（页面类型默认 / 分类覆盖 / 单页覆盖），底部入口「为当前页面新建覆盖」——3.3 回退链的 UI 出口
中组设备三段 · 缩放 · 撤销/重做 设备切换 = iframe 宽度切换（390 / 768 / 内容宽），不切数据（9.3）；缩放 = fit + 50–150% 滑条（也在状态栏）；撤销/重做带步数徽标，悬停出最近 5 步摘要
右组预览 · 快照 · 保存 预览：新标签打开无 builder 标记的前台页（真实访客视角）；快照：下拉列最近 10 份可恢复；保存按钮三态——干净（灰、禁用）/ 脏（主色，徽标 = 改动处数）/ 冲突（红，点击出取回远端 diff 弹窗）

5.1.2 左栏（模块库 / 大纲 双 tab）

  • 模块库：顶部搜索框（拼音首字母匹配，复用 nav.js 图标搜索的匹配器）；按 blocks-def 的 area 分组折叠（布局 / 内容 / 媒体 / 营销 / 工具…）；卡片 = 图标 + 名称 + 一行描述；拖拽发起 + 点击即追加到选中板块末尾（无选中则追加到最后一个板块）——点击路径同时是键盘可达路径；
  • 大纲：板块 → 栏 → 模块三层树（nav.js 摊平/重建算法复用）；行内控件：显隐眼睛（切 on）、上移/下移、删除；支持拖拽排序与跨板块拖动；选中项与画布双向高亮；
  • 底部固定入口：「存为我的板块」（选中板块，P2）、「导入模板」（P2）。

5.1.3 画布工作台

  • 灰底工作台 + 居中 iframe；iframe 内部滚动（不做全高 iframe + 外层滚动）——保真主题的 sticky 侧栏、固定头、移动端 dock 行为，这是 8.4 混合 chrome 决策的直接前提；
  • 选中框 / 悬停描边 / 投放条 / 空板块 CTA 全部画在 iframe 内（.ecod-b-* 命名空间，仅 builder 标记下注入，见 6.2）——bridge 在文档坐标系内直接画，不存在「×缩放比换算覆盖层坐标」问题；
  • 缩放实现：iframe 保持文档像素宽度，外层 wrapper transform: scale(z)；wrapper 占位尺寸 = 文档尺寸 × z（docHeight 由 bridge 上报，设备/缩放/patch 后重报），保证工作台滚动条长度正确；
  • 双击文本：不开放画布内联改文（内容仍归 Typecho 编辑器管，路由见 5.2.1），双击正文类模块 → 引导跳转内容编辑页。

5.1.4 右栏 Inspector

  • 头部：对象图标 + 名称（板块 label 可改）+ 类型徽标 + 行内三键（复制 / 显隐 / 删除，删除有确认）；
  • 标签页：选中模块 → 「内容」（params schema，EcodFields 渲染）+「样式」（supports 驱动：density / shell / hide-sm…见 4.5）；选中板块 → 「板块设置」（box + cols）+「背景」+「高级」（P2）；
  • 底部固定「设备上下文条」：桌面段修改写基础值，平板/手机段修改写入 ov（9.3 的 UI 呈现）；存在覆盖时显示「📱 手机：已覆盖 2 项 · 清除」；
  • 字段分组标题吸顶；改动即时生效（patch 片段替换）+ debounce 500ms 合并进撤销栈。

编辑器键盘编辑器5.3.1 快捷键；焦点在 iframe 内时由 bridge 转发 keydown（Esc / Del / Ctrl+Z / Ctrl+S）
编辑器内导航（切文档 / 退出 / 刷新）编辑器脏守卫三选弹窗 + beforeunload

触屏与可访问性：画布编辑仅限桌面端；模块库/大纲/属性面板全程键盘可达，拖拽均有大纲树内的等价「上移/下移/删除」按钮。hover 相关规则遵守主题的 (hover: hover) 包裹约定。

5.3 属性面板信息架构

右栏随选中对象切换，两组标签页：

  • 选中模块 → 「内容」（params schema 全量字段）/「样式」（supports 驱动的壳能力：density、shell、hide-sm…见 4.5）；

5.3.1 全局预设与快捷键（WP 构建器惯例增补）

  • Token 优先的取色器：颜色 / 背景选择器默认列出主题 token 色板（--ecod-*），自定义色为次级入口；P2 支持「存为全局预设」（options 行 ELayoutPresets，改一处全站联动）——对应 Gutenberg theme.json 预设、Elementor「全局颜色」与 Breakdance 的 token-first 模式，避免出现游离于设计系统之外的野值；
  • 样式拷贝 / 粘贴：模块右键「复制样式 / 粘贴样式」（Elementor 惯例），实现为 Store 内剪贴板对象，P2；
  • 快捷键：Esc 取消选中 · Del 删除 · Ctrl/Cmd+D 复制模块 · Ctrl/Cmd+Z / Y 撤销重做 · Ctrl/Cmd+S 保存。全部在大纲树内有等价按钮，键盘可达。

5.4 跨 iframe 拖拽（专门的硬问题）

HTML5 DnD 事件不跨越 iframe 边界——模块库（编辑器文档）与画布（iframe 文档）是两个 document，所以整套拖拽必须用指针式自定义实现（nav.js 的 pointer 拖拽算法直接复用）。分三条链路：

链路机制
模块库 → 画布
跨文档，最难		 ① 拖起：编辑器创建拖影（ghost），画布区覆盖透明 shield 接管指针；② 命中计算：bridge 事先上报 rects 注册表（uid→文档坐标，加载 / resize / patch 后刷新），shield 收到 pointermove 后换算 x_doc = (clientX − iframe视口x) / z + scrollX，查注册表得 nearestUid + before/after；③ 指示：dnd 消息下发 → bridge 画投放条；④ 释放：Store 插入 → patch 片段 → shield 撤除
画布内拖动排序
同文档		bridge 内部原生指针事件直接处理（无跨文档往返），落点确定时上报一次 move {uid, target, before} → Store 移动 → patch 受影响板块
大纲树 ↔ 画布
编辑器文档内		大纲树拖拽在编辑器文档内（HTML5 DnD 即可），落点仅更新 Store + patch，不与 iframe 实时交互

缩放下的坐标换算统一收口在编辑器侧一个 toDocXY() 函数（视口差 + scroll + 缩放三段变换），rects 注册表与拖拽共享，避免多处换算漂移。

6.2 画布模式（iframe 内发生了什么）

iframe 加载 ?ecod_builder=1 的真实页面（真实登录态、真实数据）：

  • 该标记下渲染层做三件事：① 每个板块/模块壳注入 data-buid；② 尾部注入一段很小的 bridge.js（拖放命中计算、点击上报、片段替换）；③ 屏蔽前台交互副作用（表单提交、PJAX、弹窗内链跳转改为上报）；
  • bridge.js 只在 builder 标记存在时输出，前台正常访问路径零注入、零 JS；
  • 板块样式改动（padY/bg/宽度）通过 postMessage 下发 CSS 变量热更新，不重渲染。

6.4 保存与迁移（v4 → v5）

  • 保存：文档级整存整取（不做板块级增量写），POST 携带 rev，409 时提示「已被另一窗口修改」并支持取回远端 diff——沿用 widget.js 现成的脏队列 + 冲突 UI；
  • 迁移：惰性——首次进入构建器时若 ELayouts 为空，把 v4 各区域现有实例按顺序包成「每区一个板块」的文档副本（v4 数据保留不动），用户取消则继续走 v4；
  • 快照：每次保存前自动落一份 ecod-snap-builder-*（复用 core/admin/snapshot.php，上限 10 份滚动）；
  • 本地草稿：编辑期间每次变更 debounce 写 localStorage（按 用户+文档 key 隔离，滚动保留 3 份）——WP autosave 与瓜奇 gq_builder_drafts 的共同惯例，浏览器崩溃 / 断网最多丢最后一次操作，保存成功即清除。

8 决策记录

#决策理由 / 放弃项
8.1 单数据源 + 容器查询，不做瓜奇的三设备数据树 三套树需要同步工具与冲突处理（瓜奇为此做了「同步到其他设备」整套机制），单人维护成本差一个数量级；主题已有成熟断点体系，列表减列用 container query 即可覆盖 90% 场景。板块级保留断点覆盖白名单（padY / hide，Elementor 同款「默认值 + 设备覆盖」的单文档模型，见 9.3），不做完整的三套树。
8.2 blocks 原地升级 v5，不新建平行 builder 系统 渲染端与编辑端本就分离（widget.js 自述渲染走前台块模板）；54 个模块零改动，v4 数据短路兼容，风险分散在三期而非一次重写。
8.3 板块 = 结构节点，不做成第 55 个模块 板块承载树结构（main/aside 栏），模块实例不能有 children——避免出现「模块套文档」的递归歧义；但板块的 box 参数仍走 params schema，清洗与面板复用同一套机制。
8.4 混合 chrome：选中框 / 投放条画在 iframe 内（严格命名空间），Inspector 与全部编辑控件留在编辑器侧 v1.2 修订。画布采用 iframe 内部滚动（保真 sticky 侧栏 / 固定头 / dock，见 5.1.3）后，外部覆盖层需逐帧同步滚动坐标，选框与拖拽必然抖动；Elementor / 瓜奇均把 chrome 注入预览文档。「前台零污染」约束不变：bridge 与 .ecod-b-* 规则仅在 ?ecod_builder=1 标记下注入（6.2）。
8.5 整页替换而非局部合并布局 回退链任一级命中即整页接管，语义与瓜奇一致、心智简单；「全局区 before/after」的合并语义保留在 v4 路径，v5 文档自身支持显式复用（模板导入）。

9.3 响应式模型的最终定式（8.1 修正案）

Elementor 的实践证明「单文档 + 设备后缀键」可以同时获得单数据源的可维护性与设备级微调能力，而且它并没有三套树、同步工具反而简单。据此把 8.1 从「纯容器查询」修正为三层模型：

  1. 结构性层：容器查询自动减列、aside ≤900px 自动堆叠——覆盖 90% 场景，零配置；
  2. 声明性层：板块 / 模块 ov 白名单覆盖（padY、hide、tone）——Inspector 以设备分段控件呈现（桌面 / 平板 / 手机三段，改哪个设备就写哪个设备的键），未写出的键继承桌面值；
  3. 拒绝层：完整的多设备数据树与「同步到其他设备」工具——仍不做。

实现纪律：ov 白名单是硬约束，服务端 ecod_wgt_clean_params() 同级再挂一层 ecod_layout_clean_ov() 丢弃白名单外的键——防止设备覆盖被滥用为「手机版独立设计」，那正是 8.1 要避开的复杂度。

9.4 从 WP 生态反推的两条纪律

  • 数据可出（data portability）：Beaver Builder 可导出编辑数据、Elementor 有 Kit 导出机制——不给用户数据上锁是这批产品的共同底线。本设计的布局文档 JSON + 模板导入导出（P2）即满足；同时保证「关闭构建器 / 清空 ELayouts」永远回退 v4 渲染（6.1 出口）；
  • 编辑器崩溃不伤数据：WP 的 autosave + revisions 体系被所有成熟构建器继承。本地草稿（6.4）+ 快照（6.4）+ rev 乐观锁三层兜底，加上文档级整存整取（不存在「写了一半的板块」），编辑器任何一层故障都不会产生损坏文档。

10 修正案：v6 自由行列布局（2026-11-01）

本文 §1.3 曾把「任意行列嵌套」列为非目标、§8.3 曾把「模块无 children」作为硬边界。落地后站长反馈 「中间预览区域无法随意布局」，根因是 v5 的栏模型锁死在「板块 → 主体/侧栏二分 → 栏内线性堆叠」上 （最多 2 栏、栏宽仅固定 px、模块永远独占一行）。修正案见 docs/builder-v6-design.md：在板块与模块之间插入「行 / 列」两层结构节点 （板块 → 行 → 列 → 模块，宽度 = 整数权重 fr + 可选固定 px，嵌套深度 ≤ 2）。 修订范围：§1.3（撤回行列嵌套禁令 → 受控行列自由）、§8.3（细化：并排=多列、嵌套=列内嵌行，模块仍是叶子）； 维持不变：§8.1（单数据源 + ov 白名单，白名单下沉到行/列级）、§8.2、§8.4、§8.5。
