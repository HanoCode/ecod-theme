Ecod Theme × AI 功能设计

入口：页面底部圆脸站宠（Grok Ball）· 参考 guaqi.com「问我」定位 · 2026-11-01 · 本文档含高保真页面细节设计

一句话方案：把右下角的站宠圆脸从「点击转圈彩蛋」升级为全站 AI 服务的统一入口——单击弹出AI 快问面板（轻量对话、推荐问题、余额直达签到），完整对话仍在 AI 助手页；文章页摘要卡升级为「就本文追问」；底层把 ai_chat 升级为流式输出并支持文章作用域。全部复用现有 OpenAI 兼容接口、积分计费、限速与表情球情绪契约。

0v2 修订速览 · 勘误对账

本版在 v1 设计稿上补做了一次逐行代码对账：core/content/ai.php、api.php、post.php、page-ai.php、public/header.php、public/include.php、public/footer.php、components/footer/dock.php、assets/js/ecod.global.js、assets/js/ecod.post.js、assets/css/ecod.css、build/build.mjs、core/admin/config.php。结论：方案方向成立，约 70% 可直接落地；前置条件是 1 个安全补丁，另有 3 处事实性错误与 6 处设计改动。

必须先看的三条（都带「不做就会出事」性质）：
  1. P-1 AI 是付费墙的第 5 条内容通道，目前完全裸奔。任何访客 GET api.php?action=ai&cid=<付费文章> 就能拿到全文摘要；scope=post 一旦上线，等于给付费文章开一个「无限追问」的免费全文通道。必须先补 ecod_ai_text_allowed() —— 详见 §11，不带界面、可单独验收。
  2. 面板 JS 不能挂在 post bundle 上。v1 写「aichat 已在里面」，但 public/footer.php:64 只在 is('post') || is('page') 时输出 post.js → 首页 / 列表 / 归档 / 搜索页的面板完全不会初始化（静默失败，控制台都不报错）。改挂 ecod.global.js，详见 §12。
  3. SSE 差一个 session_write_close()。ecod_throttle_* 全程持有 $_SESSION，不主动释放的话，用户提问期间另开标签页请求同站任意页会卡到 45s 超时。详见 §13。

3入口设计：页面底部的圆脸（站宠）

站宠是全站唯一「有生命感、被用户注视」的常驻元素，AI 入口放这里天然成立：它已经在「看着你」，让它开口说话只需一步。

桌面端（>680px）——单击弹面板

  • 球右上角常驻一枚 spark 角标（AI 徽记，品牌橙），暗示「这只球会说话」
  • 单击球 = 打开 AI 快问面板；打开瞬间球播 01 唤醒，面板出现后球切 35 等待输入
  • hover 球放大 1.08（现有样式）+ tooltip「问我 · AI 助手」
  • 原转圈彩蛋不删除：面板打开动效里带一次微自旋；EBallAsk=off 时完全回退旧行为
  • 首访一次性引导气泡「嗨，我是阿球，站内的事都可以问我」（localStorage 记忆，只出现一次）

移动端（≤680px）——dock 条目 + 全屏抽屉

  • 站宠在移动端隐藏是既有决策（与 dock 抢位），不推翻；AI 入口由移动 dock 承接
  • dock 新增内置 AI 条目（后台 dock 配置里给内置条目加一枚 show_ai 开关 + 文案/排序，不引入 type:ai 新类型），点亮品牌色
  • 点开为全屏底部抽屉（上滑手势可关），与桌面面板共用同一套消息逻辑，只换壳
  • iOS 输入缩放规避：输入框字号 16px（沿用既有 16px 补丁约定）

可达性兜底（重要）

  • prefers-reduced-motion：动画引擎不加载（既有逻辑），但 EBallAsk=on 时降级渲染一个静态圆脸按钮（CSS 圆 + 两枚眼球 + spark 角标），保证 AI 功能可达——功能不依赖动画
  • 键盘：EBallAsk=on 时容器渲染成真正的 <button aria-label="打开 AI 助手">（不是给 div 补 role），Enter/Space 原生可用；面板内焦点陷阱，Esc 关闭后焦点还给球 v2 改
  • 语义唯一：球只有两种身份，二选一，不能既「装饰 aria-hidden」又「唯一入口」——on = 可交互 button（内部 SVG aria-hidden）；off = 纯装饰 div + aria-hidden。详见 §14.5
  • <680px 且 dock 关闭 AI 条目：AI 助手页仍是完整入口（页头 hero 已有）

5.3 流式渲染细节

  • delta 每 100ms 批量刷一次 DOM（requestAnimationFrame 合帧），避免逐 token 重排
  • Markdown 增量渲染：维护「已完成块 / 尾部未闭合块」两段，只有闭合块参与渲染，代码块未闭合时显示裸文本 + 光标
  • 停止生成：生成中发送按钮变「■ 停止」，点击 abort fetch；预扣不回退（已产生上游成本），仅「未收到任何 delta 的上游失败」全额退回（§13.2）
  • 自动滚底：用户上滚 >40px 即暂停自动滚动，出现「回到底部 ⌄」悬浮 pill；新消息到达不再强拉
  • 失败重试：失败气泡带「重试」按钮，重试重新走预扣；不存在「失败也扣了钱又没法重试」的死角（失败即已退回）

5.4 无障碍与动效

  • 消息列表 aria-live="polite"（现状保留）；面板 role="dialog" aria-modal="false"（非阻断式，保留页面可滚动）——但复用 Ecod.dialogOpen() 必须加 lock:false，否则它加的 ecod-modal-lock 会锁掉 html 滚动 v2 补

  • 打字机/球动画全部尊重 prefers-reduced-motion：流式文本直出，球降级为静态按钮（§3）
  • 对比度：气泡内正文用 --ecod-ink 系 token；primary 底白字已过审计（沿用既有 brand 约定）

6.2 SSE 事件协议

HTTP/1.1 200 OK
Content-Type: text/event-stream; charset=utf-8
X-Accel-Buffering: no          ← nginx 不改 conf，头部即可关缓冲（预压缩白名单约定不冲突）

data: {"t":"delta","s":"段回答…"}
data: {"t":"done","reply":"完整回复全文","balance":127}   ← 只做确认，不再二次扣
data: {"t":"err","error":"接口请求失败，请稍后重试","refund":true}  ← 上游零输出才退
  • 计费口径已改（v2）：v1 的「done 前扣、中断不扣」等于开了一个免费通道——发问 → 首字到就 abort → 上游照烧 token、站点不收钱。max_tokens 封顶只能限损、不能止损。改为预扣 + 失败退回、中断不退（§13.2）
  • PHP 侧：ecod_ai_chat_call() 增加 stream 模式——CURLOPT_WRITEFUNCTION 回调里逐段解析 choices[].delta.content 并 echo + flush；FPM 下 45s 上限与旧超时一致
  • 进入流式分支立刻 session_write_close()（在预检/扣费之后、输出之前），否则同 session 的其它请求全被文件锁串行化（§13）
  • 限速沿用用户桶 aichat:{uid}；不做「全局桶 aichat:global」——ecod_throttle_* 是失败退避原语、pkey 按 IP 分散，做不出站点级速率窗口。站点级成本控制改用 EAIChatDaily 单用户日限（§13.3）
  • 旧 action=ai（摘要）要改一处：正文取值走 ecod_ai_text_allowed()，否则它仍是付费内容泄漏点（§11）

维度设计

13SSE 落地：四个阻断点 + 计费改口径

结论先给：SSE 在本栈跑得通——api.php 没有 ob_start（干净），nginx 不做 proxy、gzip_types 不含 text/event-stream、*_static 只作用于静态文件，不需要改 vhost。但有四个点必须逐个处理，其中第 2 个最致命。

#阻断点现状对策
1全局 Content-Typeapi.php:65 无条件设 application/json流式分支先 header('Content-Type: text/event-stream; charset=utf-8') 覆盖，再输出
2PHP session 文件锁ecod_throttle_* 全程持有 $_SESSION；同 session 请求串行预检 + 扣费完成后立刻 session_write_close()。不做 → 用户提问时另开标签页会卡到 45s 超时

4nginx 缓冲无 proxy；gzip 不覆盖 event-stream加 X-Accel-Buffering: no 即可，不动 vhost、不动预压缩白名单

另外：set_time_limit(60)；ignore_user_abort(false)（默认即 false——客户端断开时 PHP 在写失败处终止，正是我们要的行为）。

13.2 计费模型：预扣 + 退回 v2 改

v1 · done 前扣，中断不扣
对用户友好，但开了一条免费通道：发问题 → 首字一到就 abort → 上游照烧 token、站点一分不收。max_tokens 封顶只能限损，不能止损；脚本化批量提问即可把 key 打穿。
v2 · 预扣 + 退回
abort 刷不出免费额度；正常用户几乎无感（失败必退），只有「主动中断」承担已产生成本——这符合「用了就付」的直觉。
时机动作
预检通过、meta 事件发出后先扣 ECrAICost，meta.balance 回显扣后余额
上游失败（未产生任何 delta）全额退回，err.refund = true 并说明原因
用户中断（已收到 delta）不退回；或按已收字数比例退——二选一，不要「全退」
完成直接 done，不再二次扣

代价：402 之外多一种「已扣但失败已退」的状态要测。收益：abort 不再是免费额度。

问题现象修复
