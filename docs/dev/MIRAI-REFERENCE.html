01

结论摘要

一句话：骨架不落后，落后的是首屏整合度与阅读过程件。

值得抄（P1 五项）

  • 排序 Tab：最新/浏览/评论，后端 order 已就绪
  • 分类推荐卡：一卡承载整栏信息
  • TOC 进度 + 高亮：阅读过程件，硬差距
  • 搜索面板：热词/标签/⌘K 入口
  • Hero 首屏：轮播+搜索+数据整合为一块

已经很好了

  • 侧栏排行榜：周/月/总榜切换
  • 抽屉：遮罩/焦点圈定/滚动锁齐全
  • 卡片体系：6–9 种模式，CLS 已解决
  • 块系统：拖拽排序 + 快照，Mirai 无此物

别抄

  • Swiper：自研轮播已适配 PJAX
  • RemixIcon 整包：sprite 按需内联更轻
  • 骨架屏 79KB：真实尺寸占位已解决 CLS
  • 强制公告弹层：打断阅读

文章目录：进度条 + 当前章节高亮

P1
目录5 / 12

Mirai 做法

  • 桌面独立第三栏（内容 + 右栏 + TOC 栏），TOC 栏底部放进度条
  • 移动端：右下 FAB → 全屏抽屉，抽屉里再放一个进度条
  • 三栏会让正文变窄（1200 容器切三份）

我的设计

  • 不新增第三栏，进度条放进侧栏 TOC 卡顶部（3px，圆角）
  • 高亮用左侧 2px 竖条 + 浅主色底，比纯文字变色更易定位
  • 移动端不用 FAB：底部 dock 已占位，改为正文首屏下方一条「目录 / 进度」粘性短条
  • 不做滚动位置百分比数字（噪音）

现状缺口

  • toc.php 仅输出空壳，ecod.css:2939 明确侧栏 TOC 不做 sticky
  • 无 IntersectionObserver 高亮，无任何进度计算

05

明确不采纳

项理由影响
Swiper自研轮播已适配 PJAX 生命周期；引入 ~140KB 只换来同功能，还多一套 PJAX 对齐成本体积 +140KB
RemixIcon 整包字体包一加载即下全部字形；Ecod 用 sprite 按需内联体积 +90KB
骨架屏体系真实尺寸占位已消除 CLS，收益只剩「首屏即时感」，代价是覆盖 6 种卡片模式CSS +79KB
强制公告弹层首访打断阅读。现有顶部横幅 + hash 关闭记忆更克制—
积分/刮刮卡/商城与博客定位不符，paywall 已覆盖变现—

执行顺序

轮次内容为什么这个顺序
第 1 轮C3 目录进度 → C4 搜索面板文章页与全站的高频路径，改动局部、可独立验收
第 2 轮C5 Hero → C1 排序栏 → C2 分类卡首页信息架构一起改，避免三次回归
第 3 轮C7 相关网格 → C9 二维码 → 图片 fetchpriority/sizes零风险的细节补齐
第 4 轮C6 登录 Tab → C8 广告位依赖后端能力（OAuth 凭据 / 计数），可延后

每轮纪律不变：先补 design-proposal.html 对应章节（真源）→ 改 PHP/SCSS → build → self-check。

待你拍板（5 个设计点 + 1 个推进范围）

前 5 处会显著影响组件最终形态，第 6 处决定推进节奏。橙色项为我的倾向。

1. Hero 高度与对齐

480px 左对齐（我的倾向）能留出首条文章，但冲击力弱于 Mirai 的 550px 居中。

480 左对齐550 居中两套都做，后台选
2. 排序入口形态

浮层省空间但要一次点击；分段控件一眼可见但占一行。

浮层（下拉）分段控件原生 select
3. 分类卡是否带封面

纯列表更紧凑；带封面更"栏目化"但要求站长给每个分类配图。

默认纯列表 + 可切封面默认带封面只做纯列表
4. 移动端目录入口

FAB 与底部 dock 抢位置；粘性短条更稳但占 36px 高度。

粘性短条FAB（避让 dock 72px）沿用现有浮动弹窗

只加 Tab（注册仍跳页）改动小；完整内联注册要重做表单校验。

只加 Tab + OAuth完整内联注册维持现状

C1–C5 一起做约等于一次首页 + 文章页改版；分批做则每轮都能上线验收。
