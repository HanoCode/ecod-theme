01

结论

六站看完，判断比上一轮更明确：Ecod 的骨架与可配置性领先，缺的是「读的过程」「读完之后」「买之前」这三层。

该补（P1）

  • 排序 Tab：order 已就绪，只差 UI
  • 分类推荐卡：一卡承载整栏
  • TOC 进度 + 高亮：六站里 4 站有
  • 搜索面板：四站都有独立搜索层
  • 付费标识 F1：paywall 有，卡片上没有

本轮追加（D / E / F）

  • 阅读时长 + 点赞头像（Alright）
  • 快速评论条 + 三列 Banner（Alright / Once）
  • 运行天数 + 里程碑进度（风记星辰）
  • C2b / E1 / E2：分类变目的地
  • F2 分类色 + F3 分类工具条（B2）

已领先，别改

  • 块系统：拖拽 + 快照，六站都没有
  • 侧栏排行榜：周/月/总榜，对手都是静态榜
  • 上下篇：已带封面底图
  • 体积：原生 JS 约 60KB，B2 约 800KB

你截图的形态

  • 封面 4:2.5 + 左上角标 + 分类名 + 描述 + 篇数
  • 下接 5 条文章：圆点 + 标题 + 虚线 + 日期 + 浏览
  • 右侧「更多文章」，与分类名同排

我的调整

  • 角标不用红色：红色在本项目是 danger/上涨语义，与「阅读量」无关；改半透明黑底白字 + 模糊，压任何封面都可读
  • 「暂无描述」四个字不渲染：空描述直接省略整行，不留空位自曝内容缺失；卡片用 min-height 撑齐
  • 角标数字 = 该分类累计阅读；不想跑聚合就 badge=count 改显示篇数
  • 虚线只在行间，末行去线；日期 tabular-nums 对齐
  • 容器 <420px（3 列或移动）时降到 3 条，用容器查询而非断点猜

与 C2 的关系

  • 同一个块的两种 layout：list（紧凑，默认）／cover（专题）。不做成两个组件，避免数据层写两遍

数据成本：三个指标一次查询就能拿全

指标取法成本
篇数metas.count（Rows 已带）0
累计阅读SUM(contents.views)一次 GROUP BY
最近更新 / 本月新增MAX(created) + COUNT(created >= 月初)同一条 SQL

三者合并成一条：SELECT r.mid, COUNT(*) c, SUM(c.views) v, MAX(c.created) t FROM contents c JOIN relationships r ON r.cid = c.cid WHERE c.type='post' AND c.status='publish' GROUP BY r.mid。 分类数一般在 10 个以内，走 ecod_cache() 缓存 10 分钟即可，不进热路径。
