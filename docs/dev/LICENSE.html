01 / 概览

一句话：授权码换域名，签名文件换信任

买家在自己站点输入授权码即可解锁主题；授权码由作者后台签发，或在作者站会员中心自助购买生成。授权与域名绑定，累计可换绑 2 次；未授权时前台 503，后台保留自救通道。

作者
EcodLicenser

签发 / 续期 / 改绑 / 吊销，看得到客户在跑哪个版本。

买家
主题后台 · 授权

输入授权码或粘贴授权文件，本地验签，零网络即时出结果。

会员
会员中心 · 我的授权

选版本 → 填域名 → 付款 → 出码 → 去激活，全程自助。

边界

  • 不防破解：PHP 源码可见，真要改谁也拦不住。防的是「一份授权多处部署」—— 把一张码装到几个站上。
  • 不阻塞首屏：本地验签即时完成，联网复验在响应之后异步跑。
  • 不伤 SEO：锁死用 503 + Retry-After，搜索引擎当临时不可用，保留已有收录。
  • 永远留自救通道：管理员登录后全站可见，激活入口始终可达。
STEP 1签发后台或会员中心出码
STEP 2激活买家输入 → 本地验签
STEP 3运行全功能 + 每周异步复验
STEP 4复核域名 / 状态不符 → 503
02 / 授权模式

卖的是「一个域名的永久使用权」，不是「一份代码」

两个维度组合成商品：版本（能力边界）× 域名（空间边界）。期限恒定 —— 只有永久买断一种，不卖年付、不做到期回收。两者都在授权文件里签名锁定，改不了。

版本

专业版开放付费阅读、会员、商城、广告、卡密；团队版额外开放多作者分成。落到 modules 字段。

期限

一次买断，expire = 0 即永不到期：不续费、无年检、不做到期回收。字段保留只为兼容历史年付码。

域名

严格单域，www 与裸域互认。每张码累计可换绑 2 次，作者可单独调高。

定价（全部走设置项，留空即不提供该档）

版本价格设置项能力边界
专业版¥99 / 永久ELicPro除多作者分成外全开
团队版¥199 / 永久ELicTeam专业版全部能力 + 多作者分成
没有续费，追加销售靠两条路：① 版本升级（专业版 → 团队版，补差价 ¥100，重签同一张码、域名与换绑计数不变）；② 多域名（一个站一张码，第二张全价）。所以码必须能「原地重签升级」，而不是让买家再买一张、手工搬数据。
为什么先填域名再付款：首绑不消耗换绑次数，付款后直接拿到「已绑定、可立即使用」的码。代价是下单前必须预校验域名占用，否则付了钱绑不上。

换绑规则

项值说明
每码额度2 次累计，不按年重置；rebind_limit 可按客户单独调
已用计数rebind_used每次换绑 +1，同时写 ecod_lic_rebind 流水
旧站影响立即 503旧文件里 domain 与新域名不符，本地域名复核直接拒
换完要做的事重新激活会员中心会给出提示与直达链接
03 / 架构

主题与插件怎么对接

买家的站点没有插件，所以跨站只走一条 HTTP 端点；自助购买发生在作者站，主题与插件之间是同进程函数调用，不走网络。

│                                │  签名文件  │                                 │

│  ├ 内置公钥验签（离线）        │           │  ├ 购买 → order(kind=theme)     │

插件要给主题一个稳定入口

插件新增根文件 usr/plugins/EcodLicenser/api.php，只做三件事：定义 __TYPECHO_ROOT_DIR__ 保护、require core/bootstrap.php + core/selfserve.php、暴露 ecodl_ss_* 五个函数。主题探测文件存在就 require，不存在就返回「作者端未开启自助发码」，不白屏。

关键约束：这层只认传入的 $uid，不读 session、不读 cookie。主题已确认登录态后传进来，两边登录体系互不依赖 —— 否则同站部署时 cookie 前缀冲突会很难查。
04 / 授权文件

Ed25519 签名，买家改不动一个字节

格式沿用插件现有实现，只在 payload 里加两个字段，旧文件继续可验。

ECODLIC1.<base64url(payload)>.<base64url(ed25519-signature)>

{
  "v": 1,
  "key": "ECD-7K3M-9PQ2-XY8N",
  "domain": "example.com",
  "edition": "pro",
  "modules": {"pay":true,"member":true,"ads":true,"card":true,"shop":true,"split":false},
  "issued": 1760000000,
  "expire": 0,        // 永久买断，0 = 不到期
  "status": "active",
  "customer": "张三",
  "kid": "a1b2c3d4",
  "grace": 14,        // 新增：离线宽限天数
  "terms": 1          // 新增：条款版本
}

本地五步校验，缺一不可

#校验失败后果为什么必须
1payload.kid == 内置公钥 kidreject:kid端点返回的 pub 只用于展示；验签只用内置公钥，防中间人塞自签
2Ed25519 验签reject:sig文件被改一个字节就废
3payload.domain ≡ 当前 hostreject:domain缺这步，A 站的文件能直接搬去 B 站
4status == activereject:revoked吊销后即使文件在手也无效
5expire == 0 || expire > nowreject:expired永久码 expire = 0 恒通过；此步只为兜历史年付码
时间回拨：改系统时间能续命。对策是每次请求记录 max_seen = max(max_seen, now)，一旦 now < max_seen - 86400 直接判 invalid。

复验节奏

场景行为
每次请求只读 option（Typecho 启动时已全量载入内存，零 SQL、零网络）

6.2 购买表单：两个决定，一屏做完

用户在购买区只做两件事：选版本、填域名。前者是点选，后者是唯一需要打字的地方，所以把它放在最后、紧贴合计 —— 视线落点从「选」自然过渡到「填」再到「付」。期限不设选项：全部永久买断，少一个选择就少一次犹豫。

元素规格说明
版本卡两列等宽 · 圆角 10 · 内距 13/14选中态：主色边框 + 外发光 3px + 右上角实心勾
价格20px / 600 · 数字等宽切换版本时只改数字，「· 永久」后缀固定不动，不重排布局
版本卡副标11.5px 灰字 · 单行直接写清能力边界，不放进弹层；团队版标明「+ 多作者分成」
域名输入高 36 · 前缀 https:// 灰字分隔粘整条 URL 也能用，后端归一化去协议去路径

合计条上边框分隔 · 价格 22px永远可见，不做「展开才能看价格」
域名预校验的三种结果：① 格式不对 → 红字提示「形如 example.com」，按钮禁用；② 已被他人有效绑定 → 红字「该域名已有有效授权」并给「如果是我的，去换绑」；③ 可用 → 绿勾，允许下单。下单接口必须再校验一次，前端校验只是体验。

6.3 出码结果：一次付款，三步收尾

付款成功不跳空白页，就地展示「授权已生成」：大号授权码 + 复制按钮 + 三步激活指引。买家此刻的心理是「我现在该干什么」，所以指引必须具体到菜单路径，不能写「请到后台激活」。

必须出现的四样东西
  • 授权码（等宽字体，可全选复制）
  • 绑定的域名与版本（永久有效，确认没填错）
  • 三步激活路径（含 /admin）
  • 回列表的出口（去换绑 / 复制文件）
绝不能出现
  • 「订单支付成功，请等待发货」——没有任何人要发货
  • 只给一张订单截图，不给码
  • 支付回跳后回到空列表（要等刷新才出现）

6.4 换绑弹窗：把代价说在前面

安全要点

  1. 内置公钥 + kid 比对：端点返回的 pub 只用于展示，验签一律用主题内置公钥。
  2. 本地域名复核：验签通过后仍要比对 payload.domain 与当前 host。
  3. 时间回拨检测：max_seen 兜底，改系统时间续不了命。
  4. 订单幂等：order_no 与 key 一一绑定，重复回调不重复发码。
  5. 实例绑定默认关：开启后首个 inst 落库，换服务器会误伤，按客户开。
11 / 落地

先打通「买 → 激活 → 锁」，再谈版本分发

期范围验收
P0 插件迁移 + Verify 增强 + 主题 license 核心 + 锁死拦截 + 后台授权面板 + 在线激活 / 离线导入 / 复验 输入码 → 解锁；改域名 → 403 锁站；管理员登录 → 全站可见 + 黄条；断网 30 天 → grace 仍可用
P1 会员中心「我的授权」+ 购买 + 支付接入 + 换绑限次 付款 → 自动出码（已绑域）→ 激活成功；换绑 2 次后按钮置灰
P2 版本分发（插件 releases）+ 客户版本视图 + 一键换绑 / 重签升级 后台能看到「谁在用旧版」，可批量提醒

P0 逐文件顺序

  1. EcodLicenser/core/migrate.php → Plugin.php 接入 → 跑一次确认列齐全
  2. core/sign.php（payload 加 grace/terms）→ Verify.php 增强
  3. 取公钥写入 ecod-theme/core/license/pubkey.php
  4. core/license/license.php（验签 / 状态机 / 存储）
  5. core/license/block.php + functions.php 拦截（此时可手动测锁死）
  6. api.php 三个 license action + core/admin/config.php 面板 + admin/config.js
  7. 端到端：签发 → 激活 → 换域名 → 503 → 改回 → 恢复
P1 等 P0 验收通过再动。两期一起改，出问题时无法判断是验签逻辑还是支付链路。
